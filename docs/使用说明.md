# 使用手册

Windows x64 离线包，包含 Node.js 24.14.1、MQTT Broker 和通信驱动。先完整解压到可写目录，再双击 **00_一键启动.cmd**。浏览器打开 [本机联调台](http://127.0.0.1:19860/)。配套 [使用指南与品牌接入步骤](http://127.0.0.1:19860/guide) 也可直接打开本目录的 web/guide.html 阅读。

| 本机入口 | 用途 |
|---|---|
| 00_一键启动.cmd | 启动服务并打开网页，再次双击会复用已运行实例 |
| 01_停止本项目.cmd | 关闭这一份目录启动的服务，保存记录 |
| 02_一键自测.cmd | 在独立临时端口验证按钮、联锁、报文与通信驱动 |
| 03_查看状态.cmd | 核对当前目录对应的实例与服务端口 |
| 04_导出诊断.cmd | 网页打不开时也可把诊断报告写入本目录的 exports 文件夹 |

## 双击启动后怎样判断是否成功

窗口先显示启动进度和本次网址。看到“操作页面已打开”，表示浏览器已读到当前服务的数据并显示操作页。按任意键只关闭提示窗口，联调台会继续在后台运行。停止服务请用 **01_停止本项目.cmd**。

如果默认浏览器没有打开，启动器会尝试本机已安装的 Edge 或 Chrome。仍未显示时，把窗口中的完整网址复制到这些浏览器的地址栏。默认是 `http://127.0.0.1:19860/`，改过端口的项目以窗口显示为准。网页打不开时可用 **04_导出诊断.cmd** 导出记录。命令行只启动服务时可运行 `00_一键启动.cmd --headless`。

联调台分别显示 PLC、本地 MQTT 服务（Broker）和屏或网关的订阅状态。网页若显示“本机服务离线”，现场状态会标为“未知”，实时按钮会锁定。服务恢复后页面会自动更新。小屏幕上，六个页面入口位于顶部。

## 只有程序时，从接入助手开始

首次启动会打开[工程接入助手](http://127.0.0.1:19860/#assist)。没有工程时点 **测试本机示例**，助手会读取内置 PLC 状态，并通过本地 MQTT 发出一次查询。接过自己的程序后，同一位置显示 **检查已保存的连接**，可随时查看哪一段已经连通。

1. **提供自己的工程。** 拖入工程文件，或粘贴本机文件、项目文件夹的完整路径。同一目录可放 PLC、屏和网关程序。遇到多个版本时，根据相对路径选一份。只有 ST、XML 或脚本时，手动指定用途和品牌。助手只读文件类型和少量识别信息，原工程由厂商软件打开。
2. **选这次要测的程序。** 有 PLC 就运行厂商的 PC 仿真，有屏就运行屏工程；MQTT 由屏负责就选屏，由网关负责就选本机网关程序。缺少的部分由内置模型补上。点 **查看连接步骤**，按列出的驱动、地址、端口、设备编号和主题设置工程副本。本机已提供 MQTT 服务。
3. **从一个确定的数值开始。** 外部 PLC 可先选一个厂商监视窗口里看得到的变量，在助手中只读核对。要联调按钮和任务，再下载点表做映射。改好 IP、端口后可直接试读或点 **保存设置并检查**。外部屏可把验屏点绑定到画面的数值显示，填回读数。外部 MQTT 程序需连上本机、订阅正确主题，并按命令编号回报。最后导出接入单和检查结果，保留本次测到哪一步。

文件名可帮助识别品牌。PLC 点位、按钮报文和单位由具体项目决定。检查页显示下一步该开哪个页面，遇到问题可导出检查结果。要验证自己写的联锁与工艺，使用支持对外通信的厂商模拟器或协议桥，在其中运行工程副本。

## 用五分钟跑通一次

1. 选 **通用四键台**，按物理启动。屏上出现任务号并进入准备、作业。按物理停止，观察结束处理。
2. 再次启动后按急停。当前任务中断，按“释放急停”后故障仍为待复位，按复位后恢复正常。
3. 点 **远程启动**。在“报文记录”打开一组 command 和 reply，对照 seq。应用能区别“Broker 已确认”“设备已受理”“设备已拒绝”和“等待回执超时”。
4. 在 **项目与接入** 选择“网关模块接入”并保存。关闭“模拟触摸屏通电”，用“查询任务记录”测试独立网关。重新接通模拟屏即可恢复本地操作。
5. 选 **大田 · 按钮示例**。启动键只给许可，停止键停用。先按物理启动，再在屏上或通过 MQTT 开始。要验证水肥机完整工艺，请在厂商运行端加载自己的工程，并使用项目的点表和协议。

## 换成另一个项目

- 在“项目与接入”新建项目。四个物理键分别勾选，启动键可设为“直接启动任务”或“只给启动许可”。每键可单独设置模拟输入地址。
- 在“物联网按钮”新建、编辑或删除动作。按钮可设置名称、主题、QoS 0/1/2、JSON 或原始文本、变量、回执主题、回执关联字段与超时。可先预览，再发送。每个项目保存自己的按钮库。内置设备能应答示例协议；其他项目的指令由对应设备程序订阅、解释并回报。
- 在“项目与接入”导出配置和点表。导入配置可复制到另一台电脑。配置记录在 data/projects.json，各项目的报文与模型记录按项目 ID 分开存放。
- PLC 和屏的品牌用于选择接法。外部 PLC 模式的驱动、端口、站号和映射地址实际参与每次收发。内置模型有独立的点表和按钮逻辑；要检验原 PLC 程序，请让对应的原生模拟器或本机协议桥提供通信端口，并在测试工程内实现导出点表。

| 联调对象 | 本版提供的路径 |
|---|---|
| 西门子 S7-200、博途工程 | S7 ISO-on-TCP 读写 DB，支持机架、槽号、成对 TSAP、独立位区及字区偏移；支持 Modbus TCP 的项目也可直接使用。经典 PPI 串口型经现有 PPI 驱动或本机协议桥接入。 |
| 海为、汇川 | 在线通信的 PLC 模拟器或本机协议桥经 Modbus TCP 接入。按型号与实际工程映射位、字、站号和地址。 |
| 三菱 | MC/SLMP 二进制 3E 的 M 位、D 字，或对应 CPU 支持的 Modbus TCP。 |
| 海为、昆仑通态、威纶通屏 | 各品牌 PC 运行端用 Modbus TCP 客户端连内置 PLC。需要测试屏的 MQTT 时选“外部触摸屏”，由屏订阅并回报。 |
| MQTT 网关 | 可用内置软件网关，或将设备端切为“外部”，由本机的实际网关程序连 Broker 与 PLC。设备未应答会显示超时。 |

## 从文件导入 MQTT 协议

1. 进入 **物联网按钮 → 从协议文件导入**。拖入协议说明书，或点 **选择文件**。支持 XLSX、XLS、CSV、TSV、DOCX、DOC、可复制文字的 PDF、TXT、Markdown 和 JSON。每份最多 8 MB，可一次选 8 份。扫描 PDF 请先做 OCR，再上传文字版。
2. 左边列出识别到的消息。点其中一行，右边可改名称、用途、主题、QoS 和原文。**下发按钮**用来模拟平台发指令。**上行或回执样例**用来对照设备的上报内容。只有参数片段、方向不清或 JSON 语法有错时，先补全，或取消勾选。
3. 需要等待设备应答时，打开 **回执匹配设置**。例如指令、回执都带有同一个流水号，可以分别填 `seq`；中文嵌套字段也可以填 `数据.流水号`。没有应答的指令可以留空回执主题。
4. 点 **保存已选报文**。重复项会跳过。要发包时再从按钮库点 **预览报文**，然后手动发送。在 **报文记录** 核对发布者、实际主题、回执编号和时间。使用外部触摸屏或网关时，它订阅的主题须与导入的主题一致。

**第一次做协议表**可以点 **下载示例表格**，用 Excel 打开后把名称、方向、主题、QoS、报文、回执主题和关联字段换成项目实际值。普通 TXT 也可以分行填写“名称、方向、主题、报文”，各项用中文冒号隔开。PDF 中跨页的 JSON 可接续读取；表格版式复杂时请逐项对照原文。

文档中的实际设备号和具体主题会保留。下发示例的字符串 `seq`、数字 `timestamp` 可在预览中看到相应运行参数（10 位秒、13 位毫秒）。未标明 QoS 时暂用 0，并显示提醒。每份项目可存 48 个下发按钮和 96 条上行或回执样例。样例可以查看和删除，随项目配置导出。文件仅送到本机服务解析，导出诊断仅记录识别数量和结果。

## 怎样反馈问题

1. 记下出现问题的时间，打开“运行诊断”，勾选“只看提醒和失败”。例如，PLC 端口被拒绝、设备编号不对、订阅错主题和业务回执超时会分别显示。回到完整列表还能看到故障前后的操作和恢复时间。
2. 点“导出诊断报告”。如果网页打不开，双击 **04_导出诊断.cmd**，到 `exports` 取 JSON 文件。把文件和你记下的现象手动发给维护者即可。导出不需要联网。
3. 维护者打开“运行诊断 → 维护者汇总多份报告”，选择多份 JSON。可以按版本、系统、PLC 和屏品牌、通信驱动、MQTT 所在端查看问题分布。重叠的导出按安装编号、运行编号和事件序号去重。安装数指不同的软件数据目录，同一人可以有多个安装。

诊断使用本地生成的随机安装编号。记录涵盖平台版本、操作系统及内部版本、处理器架构、Node.js、浏览器系列与主版本、工程配置中的品牌和驱动、状态、故障分类和耗时。主动点击“检测本机软件”时，才记录匹配到的厂家软件及可确认的数字版本。原始 MQTT 报文在单独的“报文记录”页面。诊断导出采用固定字段，工程源码、文件路径、设备编号、主题、报文正文、账号、主机名和 IP 均不在诊断字段内。

诊断保存在 `data/diagnostics/`。最多保留 30 天、12 个约 256 KiB 的日志片段，每份报告导出最近 600 条。目录不可写时，运行中的网页会提示并允许导出内存里的记录。已关闭的程序只能导出成功写盘的部分。

## 端口与资料

默认网页 19860、MQTT 19883、内置 PLC 的 Modbus TCP 15502，均绑定 127.0.0.1。外部设备程序使用项目的 Client ID；默认通用示例为 LAB001，主题前缀 /sim/LAB001/。无需生产账户。实物网关或其他电脑需要单独的隔离网络接入；当前交付用于同一台电脑上的无实物联调。

端口冲突时先停本项目，修改 project.json 中的 ports 后重新启动。命令行启动可用 runtime\node.exe tools\control.cjs start --headless。关闭脚本会核对实例与路径。自测结果在 logs/self-test.json。维护代码与包锁在本目录，第三方授权随 runtime 和 node_modules 一并提供。

浏览器操作、独立 S7 协议服务和厂家现场验收的范围见[验证记录](验证记录.md)。
