# 1.5.0 验证记录

验证日期为 2026-11-06，运行环境为本机 Windows x64、随包 Node.js 24.14.1。自动化测试使用独立端口、账户标识和数据目录。联调过程中没有连接生产 PLC、实际泵阀或云平台。

| 验证范围 | 实际做法与结果 |
|---|---|
| 界面与断线 | 在 320、390、768、1024、1440 像素宽度切换六个页面。在协议核对窗口验证“保存”的位置，核对急停释放、首次试跑入口和键盘跳转。中断浏览器状态请求，确认三段通信和设备读数转为未知、实时操作锁定，恢复后重新按项目状态启用。 |
| 一键自测 | 72 项通过，含原有 62 项以及 10 项文档导入与中文通信回归。详细断言随包保留在 tests。 |
| 协议导入 | 实际读取两种 Excel、CSV/TSV、Word 新旧格式、Markdown、TXT、JSON 和一份 19 页中文文字版 PDF。在浏览器核对跨页正文、控制与回执的主题以及 QoS。验证勾选、取消、改名、保存、刷新恢复、重复导入和手机宽度。图片型 PDF 提示先做文字识别。 |
| 中文数据 | 验证含中文、空格、标点的路径，UTF-8/UTF-16/GBK 文件、中文主题与中文关联字段。用独立 MQTT 客户端收取导入的命令并带同一流水号回执。 |
| Windows 启动入口 | 复现旧版在浏览器打开失败时仍返回成功。验证默认浏览器页面回执、备用浏览器、手动访问提示、双击窗口按键后关闭及无界面启动。 |
| 物理四键 | 通过 Modbus 真正写位。检查直接启动、许可启动、停止、急停按下、急停释放及故障复位。网页或 TCP 向内置模型写入已停用的键都没有动作。 |
| MQTT | 真实 Broker、独立发布端和订阅端。核对命令编号、返回主题、错号回执、同号重发、文本、参数类型、无回执超时、掉线与恢复。 |
| 触摸屏与网关 | 启动内置屏与内置网关两种模式。模拟屏断电时，屏负责的 MQTT 连接断开；独立网关继续回报。外部模式由独立 MQTT 客户端通过 Modbus 提交任务并发布回执，未启动客户端时实测超时。 |
| Modbus TCP | 独立软件 PLC 使用站号 7、非默认基址、非连续物理按键地址，接收四键和来自 MQTT 的任务请求。版本、站号或连接有问题时显示通信异常。 |
| S7 ISO-on-TCP | 使用独立的 python-snap7 2.1.0 服务端，实际经 TCP 读写 DB100/DB101。通过急停位按下/释放、参数与任务号回读、请求号与应答号匹配、结束握手。拒绝连接时返回通信失败。可用 tools/verify_s7.py 复测。 |
| 三菱 MC/SLMP | 通过独立的本地二进制 3E 报文测试端交换 0401/1401 帧，检查 M 位按下/释放、D 字参数、字节序、提交及任务号。 |
| 浏览器 | 在 Chromium 中实际点击。覆盖四键、两种启动、禁用停止键、屏上启停、MQTT 回执、按钮编辑/预览/发送/删除、报文原文、网关独立运行。验证首次快速检查与已接工程的只读检查，核对项目设置未变；验证错误路径修正和粘贴路径后直接继续。另走通选择多个工程版本、粘贴本机目录、下载点表、试连诊断、验屏和导出。在浏览器实际导出报告并导入两份重叠数据，汇总显示一个安装且事件正确去重。检查桌面布局、390 像素宽的六个页面以及助手各步骤。可用 tools/verify_ui.py 复测。 |
| 工程文件识别 | 在包含多版本的测试目录实际检出 5 份 PLC 候选和 2 份触摸屏候选，保留相对路径供选择。通用源码、共享扩展名和同一工程的多个版本均有人工确认入口。 |
| 分段诊断 | 实测区分“TCP 能连但点表不匹配”、设备编号错误、订阅主题不对、其他客户端发回同号报文、配置设备真正应答和本次查询超时但曾有旧回执。单点试读经实际 TCP 验证 Modbus、S7 和 MC 地址。未启用测试点表的程序也可先对读一个变量。 |
| 验屏 | 在 Chromium 发起验屏，独立 Python TCP 客户端读取本次寄存器，再输入读数。仅后台轮询或填错数值均无法通过。原生 PLC 与原生屏同时接入时，结果标为“人工对照”。 |
| 运行诊断 | 实测按下和释放急停、PLC 断开与恢复、MQTT 应答、错误发布方、未保存的三菱 MC 驱动试连。只记录固定故障类别和状态。 |
| 报告边界 | 使用含私有设备号、路径、IP 和报文的测试数据检查日志文件与导出。验证了轮换、损坏末行可恢复、目录不可写时保留内存记录、同一安装重启后可连接事件以及多安装去重。 |
| 数据隔离 | 项目切换、配置导入导出、各自的按钮库与点表、活动任务拒绝切换、旧网页请求失效，均已验证。 |

## 验证边界

本次执行了通用 PLC 模型、本机 TCP 协议端和浏览器测试。海为、昆仑通态、威纶通的具体画面工程，以及西门子、海为、三菱、汇川的具体 PLC 原生工程，需分别使用对应厂家的运行端加载工程，核对实际点表和驱动能力。物理网关、实际接线、掉电行为与实物急停另行现场验收。纯 PPI 串口型需另备 PPI 通信路径。

Windows 离线包另在带空格的中文临时目录解压，在只保留 Windows 系统目录的 PATH 下依次检验一键启动、重复启动复用同一实例、查看状态、识别工程、只读 MQTT 查询、一键自测、导出诊断和停止。在线工作目录保留原项目配置与按钮。
